# ADR-001: System Architecture Style — Modular Monolith

## Status
Accepted

## Context
The application (BioVault Lab) is an offline-first desktop tool designed for A standalone desktop and local-network laboratory specimen inventory and chain-of-custody tracking tool for diagnostic pathology labs. It tracks bio-specimen accessioning, freezer cold-chain temperature logs, custodian sign-offs, and regulatory compliance audit exports. [NFR-04]. The target scale is tier T0 (< 10,000 DAU, The local system must support at least 10,000 specimen records) with 100% local persistence and zero external cloud dependency [NFR-02]. We must choose between a Modular Monolith and a Distributed Microservices architecture.

## Options Considered
1. **Modular Monolith (Chosen)**: Single deployable desktop application with well-defined internal domain module boundaries (Specimen check-in with 2D barcode generation, Cold-storage temperature excursion logging, Custodial transfer sign-off with digital confirmation, Regulatory inspection audit export).
   - *Pros*: Zero network hop latency; trivial atomic transactions; zero container/Kubernetes orchestration overhead; 100% offline reliability; fits within budget and 4 weeks MVP timeline.
   - *Cons*: Horizontal scaling across multiple machines requires future refactoring if multi-user cloud sync is added in v2.
2. **Microservices Architecture**: Multiple distributed services communicating via HTTP/gRPC with container orchestration.
   - *Pros*: Independent service deployment and scaling.
   - *Cons*: Severe violation of Handbook Section 7.2.6 (Must Not over-engineer); introduces network latency, distributed data consistency failures, complex IPC, and heavy memory footprint unsuitable for offline field workstations.

## Decision
Adopt a **Modular Monolith** architecture pattern. The system runs as a unified desktop process with clear internal domain separation.

## Consequences
- Single-process execution guarantees instant in-memory operations and direct embedded database transactions.
- Zero network failures or IPC serialization overhead during offline client operations.
- Development fits comfortably within the target delivery timeline and budget [G-01].
