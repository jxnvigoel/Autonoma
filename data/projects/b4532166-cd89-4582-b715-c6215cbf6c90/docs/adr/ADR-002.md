# ADR-002: Desktop Client Runtime & Core Language Stack

## Status
Accepted

## Context
Per [NFR-04], BioVault Lab must execute locally on macOS Desktop with full offline capability and responsive UI latency (< 1.0 s per [NFR-01]). We must select an application execution runtime and frontend/backend stack.

## Options Considered
1. **Desktop Web Runtime with TypeScript/React and Local Engine (Chosen)**:
   - *Pros*: Rich component ecosystem; strict type safety; rapid UI delivery; native responsiveness with local file access; WCAG 2.2 accessibility compliance [NFR-05].
   - *Cons*: Requires packaging desktop bundle.
2. **Pure Web Browser Cloud Application (SaaS)**:
   - *Pros*: No desktop installation.
   - *Cons*: Fails [NFR-04] (offline execution in subterranean basements and remote construction sites); violates client data privacy constraints [NFR-02].

## Decision
Implement the application interface in TypeScript and React with a local runtime engine providing direct filesystem persistence.

## Consequences
- Guaranteed offline availability regardless of job-site cellular or WiFi signal.
- Strict typing prevents runtime null pointer exceptions across inspection forms.
